# 动机图（P5）：先问证据是什么，再选形式

动机图没有固定样式。雷达图、数据集缩略图、"朴素做法 vs 本文"框图只是其中几种；**形式由动机的证据决定**。一张动机图只证明一件事——通常是 prereg §0 的现象（"现有方法在 C 条件下失败"），或 gap_map 的失效点。

## 第一步：写一句 claim

动手前先写一句话，放进 figures.csv 该图的 issues 列开头：

> <现有做法> 在 <条件> 下 <怎样失败 / 被迫取舍>，<量级>。

例："朴素拼接在 42 个检测器×数据集组合里全部低于较好的单模态，平均 −18.1 AP。" 写不出量级，说明证据还没测，先回 P3 做 prereg §0 的最小对照实验，或用 `failure_slice.py` 切出失败的那一片。

## 第二步：按证据选形式

| 动机的证据 | 形式 | 工具 |
|---|---|---|
| 测出来的现象随条件变化（剂量、光照、噪声、窗宽、遮挡、时间、分辨率） | 条件曲线：指标 vs 条件，标出领先者在哪里换人、差距、区间 | `make_motivation.py condition` |
| 同一批对象在两种设置下的变化（单模态 vs 朴素融合，全剂量 vs 低剂量，域内 vs 域外，干净 vs 退化） | 斜率图（≤12 项）或排序 Δ 柱（更多项），直接写"几项变差" | `make_motivation.py paired` |
| 现有方法被迫在两个量之间取舍（精度 vs 参数 / 算力 / 时延 / 标注量） | 权衡散点 + Pareto 前沿 | `make_motivation.py tradeoff` |
| 现有方法肉眼可见地失败（伪影、漏检、错配） | 失败案例网格：输入 / 基线 / 本文 / GT，局部放大 | `make_comparison.py grid --inset` |
| 本文在结构上是另一种做法（范式对比） | 示意框图："现有做法 vs 本文" | `make_motivation.py schematic`（YAML，模板 templates/motivation_scheme.yaml） |
| 新数据 / 新模态本身就是动机 | 数据样例条 | `make_motivation.py strip` |
| 结果的广度（多基准全面领先） | 雷达或分组柱 | `make_motivation.py radar` / `make_figure.py main` |

最后一行是**结果预告**，不是动机：它说明"我们赢了"，不说明"为什么需要我们"。

**本地样本**（`figure-norms-per-figure.csv`，344 篇 CS 论文的 Fig. 1，粗分类，27% 未分类）：架构 / 流程总览 38%，定性结果与样例 9%，定量对比 8%，概念示意 5%，概念 + 数据图 4%，现象曲线 3%，失败案例 2%，特征 / 注意力可视化 1%，权衡散点 1%；雷达图不到 1%。所以 Fig. 1 常常不是动机图（而是架构图），动机图也极少是雷达图。

## 选择顺序

1. **有测量就用测量。** 审稿人信数字多于示意图；条件曲线或成对 Δ 能一眼看出"坏在哪、坏多少"。
2. **测量 + 概念可以拼成两块**：左边示意（本文怎么不同），右边数据（为什么需要）。每块一个 PDF，`latex_check.py figure --panels a.pdf,b.pdf --width 0.45,0.53 --env figure*`。
3. **纯示意只在现象没法测时用**，而且示意里的东西不能冒充数据。
4. **完整实验另放。** 动机图只放最小的那一截（一个数据集、一条条件轴），题注指向实验节的完整版本。

## 检查清单

1. **一眼测试**：不看题注，5 秒内能说出"哪里坏了"吗？差距、换人点、"几项变差"要直接标在图上（脚本自动标），不要只靠题注。
2. **题注第一句就是 claim**，带数字；数字来自脚本打印的汇总和 `.source.csv`，登记进 numbers。
3. **一图一个 claim**。第二个 claim 另起面板或另起图。
4. **不夸大**：
   - `condition` 标为 inside seed noise 的换人点不画、不能写成"反转"；单次运行的换人点标 "(1 run)"，补 seed 前不当结论。
   - `tradeoff` 里本文不在 Pareto 前沿上，就不说"更优的权衡"。
   - `radar` 里本文不是每根轴都最好，就不说"外包络"；每根轴是各自缩放的，题注要写明。
   - `paired` 的项不独立时（同一检测器出现在多个数据集），"42/42 变差"是描述，不是显著性检验。
5. **看起来像数据的必须是真数据**：输入对来自数据集；"错误 / 正确检测"是两个模型在同一帧上的真实输出；特征图是真实特征图。示意色块（`tile`）在题注里写明是示意，脚本会在 figures.csv 的 issues 里提醒。
6. **位置**：会议稿放第 1–2 页（通栏 `figure*` 或单栏顶部），引言第 2 段（现有方法的具体失败）引用它；期刊可放引言末或方法节之前。
7. **印刷宽度**：按版心画（单栏 88 mm 左右），脚本会把轴缩到紧框不超宽；G5 照常查最小字号。

## 例子（换成你项目的现象）

- 冻结的基础模型特征随剂量降低而变差 → `condition --x dose --y AUROC --series encoder`，标出最差剂量处的差距。
- 显示窗宽改变了下游结论 → `condition --x window --y Dice --series task`，看领先者是否随窗宽换人。
- 朴素融合比单模态还差 → `paired --from RGB,IR --to fused`（较好的单模态 vs 融合），斜率图或排序 Δ。
- 现有融合模块又大又慢 → `tradeoff --x params --y AP --logx`。
- 门控在退化下不开 → `condition --x degradation --y gate_value --series model`，加 oracle 作参照线。
