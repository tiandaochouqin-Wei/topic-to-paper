# 审稿（P7 / S6）：内置流程与席位

**本 skill 自带完整的模拟审稿流程，不依赖外部 skill。** 本机若装有 `academic-paper-reviewer`，两者等价、可任选其一；产物格式相同，`review_check.py` 照常核对。评分口径见 [review-rubrics.md](review-rubrics.md)。

目标不是写一份"像审稿意见"的文字，而是找出审稿人真会抓的、能让稿子被拒或降档的问题，并改到关闭。只有赞美和泛泛建议的审稿是失败的审稿。

## 流程

1. **盲读**：先只读 `paper/manuscript.md` 与图，**不开** prereg、claims.csv、runs/ 等作者材料。在日志开头写 `## Blind read` 三行：一句话贡献；审稿人 5 分钟后会信 / 不信哪条主张；摘要承诺的在正文兑现了没有。（防止被作者框架带着走。）
2. **逐席审**：下面各席位独立成节，只问自己的问题；每席先写一行"如果我要拒这篇稿子，最强的一条理由"。席位后再看"必须回到的文件"核对证据。
3. **每条意见满足五点，否则不写**：
   - **定位**：§x.y / Table n / Fig n / 行号。
   - **被攻击的主张**：引用或转述正文原话，不是笼统的"实验不够"。
   - **后果**：一句话，说为什么审稿人在意（结论不成立 / 不可复现 / 贡献不清）。
   - **怎样才算解决**：具体动作（"加 X 对照，预期读数 Y"、"把 §3.2 的'任何'限定到 …"）。给不出的就是泛泛之谈，删。
   - **严重度**：`[major]` = 不解决会使结论不成立、结果不可信或稿子被拒；`[minor]` = 清晰度、措辞、格式。major 一般 3–8 条，超过 10 条是在凑数，合并或降级。
4. **先核实"缺失"类意见**：写"没比较 X / 没报告 Y / 没引用 Z"之前，先在正文、附录、补充材料里搜一遍；搜过的在意见里写"已在 §… / 附录全文搜索 X，未见"。冤枉作者是自审最常见的假阳性。
5. **R5 编辑综合**：一张表 `编号 | 严重度 | 席位 | 一句话 | 处置计划 | 工作量 | 投稿前必须做`，再给建议档位（[review-rubrics.md](review-rubrics.md)）+ 置信度 + 一句话理由 + 投稿前最该做的三件事。区分"不做必被拒""做了明显加分""可留给 rebuttal"，不要全排成必须做。
6. **处置与改稿**（用户让改才改）：见下"处置词表"。改完 `state.review.round` 加 1，G6 重跑，写 `## Re-review`。
7. **复审**：读改后的稿子，对上一轮每条 major 写一行 `R1-1 closed: <改后位置与依据>` 或 `R1-1 OPEN: <还差什么>`；另查**改稿引入的新问题**（新增主张有无证据、改过的数字是否同步到摘要和结论、删内容后有无悬空引用），新问题同样标 [major]/[minor] 并给处置。

## 研究稿席位

| 席位 | 只问这些问题 | 必须回到的文件 |
|---|---|---|
| R1 方法学 / 统计 | 主张的作用域有没有越过数据集与口径？每个"更好"有没有 n、seeds、检验？消融格是否在 seed 噪声内却被解读？消融是否一次只改一个因素、对照是否同等调参？含命题的稿子：每条命题是否独立重推过证明（量词、期望还是概率、比值损失的分母）？正文里的"不可能/任何/从不"是否逐句对到某条命题？置信区间的重采样单位是否等于 prereg 写的单位（患者 / 场景，而不是切片 / 帧）？经验陈述里的"从不/每一对/所有任务"在换一个预测器或缩小测试集后是否仍成立？有无多重比较、事后挑指标、只报最好的 seed？ | results/main.csv、ablation.csv、prereg.md §3/§4/§7、paper/theory_notes.md、分析脚本的重采样代码 |
| R2 领域专家 / 新颖性 | 问题是否真实、是否已有人系统回答（gap_map 的饱和计数）？**最接近的三篇已有工作是哪几篇、差异是否站得住**（实际检索，不凭记忆断言）？基线是否漏了邻域里被比最多的（mined/baselines.csv）、是否同等设置？贡献点（新方法 / 新发现 / 新数据）与实验对得上吗？声称的"现有方法失效点"有证据吗？ | literature/gap_map.md、problem_table.csv、mined/ |
| R3 复现与泄漏 | 划分键、泄漏开关、关键超参是否生效、硬件是否混用？早停与调参是否碰过测试集？预处理统计量（归一化、窗宽窗位）是否只在训练集估计？数字能否溯源？代码、权重、预算是否可得？ | audit_check / results_check 的输出、runs/*/args.json |
| R4 写作与形状 | 章节顺序与家族画像是否一致？摘要→引言→贡献→实验→结论是否一条线？引言是否点名每篇关键论文的失效点（不是"现有方法有局限"）？图是否单看图与图注就能读懂、是否都被正文引用？缩略语？局限节是否诚实？版式、双盲是否合刊要求？ | shape_check、draft_plan check、gate_check 的输出 |
| R5 编辑 | 一句话说得清贡献吗？对该刊读者重要吗？局限节是否覆盖预注册的失败分支？有无过度宣称？投稿文件与正文一致吗？综合出档位与三件事 | paper/claims.csv、prereg.md §8、submission/ |
| DA 魔鬼代言人 | 构造对这篇稿子**最有力的反驳**：结论能否被更简单的解释取代（数据偏差、弱基线、指标选择、泄漏）？哪个实验做了会推翻主张、作者是否回避？哪篇已有工作或哪组数据能直接反驳核心论点？去掉最亮眼的结果后剩下的够发表吗？只写 1–3 条，每条给出"怎样才能反驳我" | 全部 |

## 综述稿席位

| 席位 | 编号 | 只问这些问题 |
|---|---|---|
| 领域编辑 | R1 | 这是综述还是目录？论点一句话是什么，能被证伪吗？ |
| 方法学 | R2 | 检索式、日期、计数能复现吗？纳入规则可机械判定吗？编码表每字段有取值集合吗？κ 多少？ |
| 领域专家 | R3 | 漏了哪些该纳入的工作？已有综述表是否齐、差异是否成立？ |
| 读者视角 | R4 | 读完能据此选方法吗？覆盖矩阵的空白格有没有变成路线图？ |
| 魔鬼代言人 | DA | 论点能否被某篇已有综述或某组被纳入文献直接反驳？ |

## 处置词表

| 处置 | 含义 | 约束 |
|---|---|---|
| 已改 | 已在稿中改动 | 写改在哪（§ / Table / Fig） |
| 复核通过 | 复核后意见不成立，或稿中已有证据 | 写稿中哪里有证据 |
| rebut | 不采纳 | 引用结果文件或论据，不能只写"不同意" |
| partial | 部分采纳 | 写明采了哪半、没采哪半及原因 |
| 需新实验 | 要补实验才能关 | 未补之前 major 不得写 closed；补完在复审节关闭 |

红线：不编造实验结果、数字、引用；不用改措辞去"关闭"一条本来需要证据的 major；改数字回到结果文件和 numbers 登记，不在稿子里手改。

## 自审的已知失败模式

- **自我欣赏**：写出一堆"总体不错，但可以…"就说明没在审 → 每席先写最强拒稿理由。
- **锚定作者框架** → 先盲读。
- **严重度通胀 / 凑数** → major 数量约束。
- **假缺失** → 第 4 步先搜。
- **只有方法学、没有新颖性** → R2 必须真的去检索最接近的工作。
- **档位偏乐观**：自审倾向高估一档，拿不准往低估，并写出"什么证据能升一档"。
- **同一个模型审自己写的稿，盲点相同**。要更独立的意见：开全新会话只给稿子，或交给 `nature-reviewer`；汇报时如实说明这是同一模型模拟的审稿，不等于真实审稿结果。

## 产出格式（paper/review_log.md）

`review_check.py` 认的结构：席位标题 `### R1 …` / `### DA …`；意见是编号行 `1. [major] …`，编号与席位拼成 `R1-1`；处置在同行或后两行；复审节标题含 `Re-review`。

```
# Review log — round 1 (<日期>, 口径: <官方表 / 通用口径>)

## Blind read
- 一句话贡献：… / 5 分钟后会信、不信：… / 摘要承诺 vs 正文兑现：…

### R1 方法学 / 统计
最强拒稿理由：…
1. [major] <定位>：<被攻击的主张>。<后果>。解决办法：<具体动作>。处置: 已改 (<改在哪>)
2. [minor] <意见> → rebut: <理由，引用结果文件>

### DA 魔鬼代言人
1. [major] …

### R5 编辑 — 综合
| 编号 | 严重度 | 席位 | 一句话 | 处置计划 | 工作量 | 投稿前必须做 |
建议档位：… （置信度：高/中/低）；理由：…；投稿前最该做的三件事：1) … 2) … 3) …

## Re-review (round 1)
- R1-1 closed: <改后位置与依据>
- DA-1 OPEN: <还差什么>
```

`review_check.py` 的行为（别踩）：
- 行内 `→ 已改 / closed / fixed` 把该条直接判为已关闭、不经复审（EAAI 真实日志依赖此行为）。**major 写 `处置: 已改 (…)`，不用箭头**，这样才逼出复审；仍用箭头时脚本给 WARN（复审节没逐条核对）。
- 复审节里没关的 major 写 `OPEN: …`。含否定的句子（`NOT closed`、`未关闭`、`尚未`）在 2.9.0 起不再算关闭，但 `OPEN:` 一行里仍避免出现 closed / 关闭 / 已改 / 通过 等词，免得歧义。
