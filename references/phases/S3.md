# S3 筛选与编码 — 细则

> SKILL.md 索引表的全文版，从 v2.5 的 SKILL.md 原文逐字下沉；进入 S3 前读完本文件再动手。综述关口的判据见 [../gates.md](../gates.md)（综述分支关口一节）。

分两级：标题级（规则 + 人工）、摘要级（人工）。`coding/screening_sheet.csv` 每行 decision ∈ {include, maybe, exclude} + reason + screen_pass。纳入的进 `coding/coded.csv`，字段 = codebook。生成 PRISMA 计数（`literature/prisma_flow.json`）。
零 token 的部分交脚本：规则预筛、去重、DOI 修复（PubMed efetch 限定 PubmedData）。要判断的部分 Claude 在本会话内按批做，每批写回 csv，不开子代理。
G-S3 = `survey_check.py coding` 全绿：screening 每行 decision+reason；coded 每行每字段的值 ∈ codebook 取值集合；PRISMA 四个数相加对得上；κ 样本已编且 ≥0.6（否则 codebook 要改）。

**脚本化（2.7 新增）**：标题级规则预筛用 `survey_search.py triage --include-any "<词,词>" --include-all "<词>" --exclude "<词,词>" --since <年>`：命中排除规则的行 decision=exclude、reason 以 `rule:` 开头；其余 decision=maybe 留给 Claude 按批做标题/摘要筛选（写回 `coding/screening_sheet.csv` 的 decision/reason/screen_pass）。再跑 triage 不会覆盖 Claude 已决的行（reason 不以 rule: 开头的）。triage 同时更新 `literature/prisma_flow.json`：identified = 各源 fetched 之和、deduplicated = candidates 行数、screened_title = 全部、screened_abstract = 过了规则的、included = Claude 的 include 数；G-S3 核对这五个数的单调性与 included = include 行数。

**筛选质控（2.11 新增，借自 Imbad0202 sr-screener）**：
- **pending 不是 exclude**：调用失败、拿不准、等复核的行写 decision=pending。有 pending 时 G-S3 FAIL，PRISMA 与方法节不出终值——失败静默算 exclude 是综述筛选最隐蔽的漏检。
- **排除复核**：同一个模型筛两遍会犯同样的错，两遍一致不能证明排除是对的。`survey_tables.py qc-sample --n 100 --near-miss "<核心标准1的词|同义词>;<核心标准2的词|…>"` 抽 near-miss（每组至少命中一词的排除记录）+ 固定 seed 的随机排除样本，写 `coding/qc_exclusion_sample.csv`，**不带原决定与理由**。按协议逐行填 qc_decision / qc_reason（复核时不回看 screening_sheet）。判 include 的要回 screening_sheet 改成 include/maybe 并重算 PRISMA，否则 G-S3 FAIL；误排 > 0 时 WARN，正文报误排率，同类记录整层重看。systematic / scoping 无此文件 FAIL，narrative WARN。
- **κ**：`survey_tables.py kappa --b coding/coded_second.csv --fields <字段,…>`（筛选一致性用 `--a/--b` 指向两份 screening sheet、`--fields decision`）。写每字段 κ、一致率、PABAK；多值字段按集合比较。κ < min_kappa 但 PABAK ≥ 0.8 是一个类别占绝大多数造成的（患病率悖论），G-S3 降 WARN，正文三个数都报。
