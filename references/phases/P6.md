# P6 写作 — 细则

> SKILL.md 四行表的全文版，从 v2.5 的 SKILL.md 原文逐字下沉；进入 P6 前读完本文件再动手。关口判据与历史漏法见 [../gates.md](../gates.md)，失败模式总表见 [../lessons.md](../lessons.md)。

**论点先行（G6g，`argument_check.py`，2026-10-28 新增）**：顺序是 claims.csv → `paper/argument.md` → 提纲 → 正文，不是倒过来。三个真实 CVPR 草稿的毛病是清单驱动：gap_map 每行变成引言里一句"点名某篇并说它的失效点"（1000+ 词的人名目录），每条主张的数字都塞进贡献条目（4–14 个数字一条），没有人要求一句话的主张、也没有"读者的问题"。所以写正文之前先把 `templates/argument.md` 复制成 `paper/argument.md` 填好：一句主张（≤35 词、≤2 个数字、有可证伪的动词）、读者的问题、读者应该记住的一个数字（headline，必须是 claims.csv 的一行）、为什么读者本来不会信、最强的反对意见与答在哪、不主张什么、引言每段一条提纲。正文必须照它写，标题 / 摘要 / 引言末段（贡献列表之前）/ Conclusion 开头共用那一句主张；故事变了，先改 argument.md 再改正文。`argument_check.py` 作 G6g 核对这些位置、数字取整、提纲顺序，用词元重合——它查的是论文前后一致，不是论点好不好（那是 P7 独立审稿的事）。有稿无 argument.md 时 G6g 直接 FAIL，have_draft 入口也一样：给已有稿子补写 argument.md 是第一步。

**P6 写作**：**先按 family 取骨架** `templates/skeleton-{cs_conf|cs_journal|nature}.md` 作 manuscript.md 起点（nature：Abstract ≤150 词一段 → 无标题引言 ≤600 词末句 "Here we show" → Results 小标题是主张句 → Discussion ≥12% → Methods 在最后；不写 Related Work / Conclusion / 贡献列表 / 正文公式 / "state-of-the-art"，消融写 control experiments，每个比较给 n、检验、p 或 CI。cs_conf：Intro 末尾贡献 3–5 条 → Related → Method 带公式 → Experiments 含 Ablation 小节 → Conclusion，主文 8–10 页附录放全表。cs_journal：同 cs_conf 但 Related 展开 2.1–2.3、Problem Formulation、实验 8–11 小节、Discussion/Limitations 子节、摘要 ≤250、Highlights 另文件）。顺序固定：① 填 claims.csv（每条主张：陈述、数据集、口径、证据文件、表/图、作用域词）；② `draft_plan.py plan` 从 gap_map / prereg / claims / results 自动生成**各节必写清单** paper/draft_plan.md（引言：重要性行、Related Work 按主题组织（主题句 → 2–4 篇 → 它们的关系 → 我们的不同；关键论文的失效点在相关工作或引言里点名即可，WARN）、引言至多点名 3 篇且每段至多引 6 篇、§0 现象、§1 主张一句话、argument.md 的主张句与读者的问题、主打主张（headline）的数字进贡献条目（其余主张的数字留给 Results）；方法：§0 原因假设作动机段、每个有消融的组件、借来方法的失效点与修法；结果：每个预注册基线与消融的名字、ours 相对最强基线的相对变化、不可分辨的消融格必须写"not resolvable / within seed noise"、失败切片与"模型知不知道"；局限：预注册失败分支、五维弱项）；③ 按清单写各节，引言用 `academic-intro-writing`、各节 `nature-writing`、润色 `nature-polishing` 作可选辅助；④ `draft_plan.py check` 逐项核对（词元重合或精确数字，章节对才算），缺的 FAIL = G6b。清单抓的是"该说的没说、说错了章节"，说错了数字由 G6 numbers/scope 抓。**对比/消融表不要手写**：`make_comparison.py sota|multi|ablation|seeds --csv results/x.csv --out paper/tab_x.tex --md --numbers`（sota=单数据集 SOTA 表，按 --group-col 分 CNN/Transformer 组、--extra Params,FLOPs、最优红/次优蓝、--ours 加粗置底；multi=多数据集并排；ablation=✓/× 组件表、全 ✓ 行加粗；seeds=逐 seed + Mean±Std；--labels 'AP50=AP$_{50}$' 换表头）。`--numbers` 把每格登记进 paper/numbers.csv，G6 直接溯源到 `<out>.source.csv`。G6 = `gate_check.py all`（refs/floats/acronyms/scope/numbers/limits）。**G6e = `claims_check.py`**（2026-10-11）：claims.csv 每行填 `evidence_key`（`rel:rmse_E1:ours:baseA`、`z:rmse_E1:no_dom`、`mean:`、numbers.csv 式单格）与 `expected`（`-19.2±0.2`、`>=2`、`<2`、`+`），关口自己算；正文里每句 "Here we show" / 贡献条目 / "outperforms all" 类强作用域句都必须能对到一行，强作用域行的 scope_words 写清"all = 哪几个基线、哪个数据集、哪张表"。定性主张（§0 对照、协议类）留空 evidence_key，关口 WARN 不 PASS，审稿席位人工看。

**LaTeX 投稿形态（2.7 新增）**：有模板的刊，正文写在 `paper/latex/main.tex`（可 `\input` 分节文件与 figs/*.tex），图只用 `\includegraphics{*.pdf}`。`paper/manuscript.md` 是派生品，不手改：每次改完 .tex 跑 `tex_to_md.py paper/latex/main.tex . --bib paper/refs.bib`（展开 \input，主题注取最后一个 \caption 并附子题注，figures.csv 合并保留 source_data / inspected，项目 bib 不改写），再 `t2p.py check`。G6d = `latex_check.py check`：class 对刊（state.target.latex_class 不符 FAIL）、每张图存在且为 PDF、含 ≥2 张图的 figure 必用 subfigure/subfloat 且包已加载、题注 (a)(b) 对单图 FAIL、\ref 不悬空、bib 文件在、manuscript.md 不比 .tex 旧。表格仍由 `make_comparison.py` 出 .tex 直接 `\input`。

**伪代码（Algorithm，`make_algorithm.py`，2026-10-23 新增）**：方法是一个带循环 / 分支的过程、散文说不清时才加；已发表论文里有伪代码的方法论文占比见 `references/algorithm-norms.csv`（cs_conf 约 18%、cs_journal 约 29%、Nature 系 <1%，ICML/TKDE/InfoFusion 最高 36–59%），`shape_check.py` 在该家族 ≥50% 的方法论文有而本文没有时才提示。流程：① 在 state.algorithms 登记一行 `{id, source: file:function, tex, params}`，source 是跑出结果的那个函数；② `make_algorithm.py skeleton --id <id>` 按函数的语句写出 `paper/latex/alg_<id>.tex`（每个顶层语句一行，源码行放在 `% code:` 注释里；方言取自 main.tex 的导言区：algorithm2e / algorithmic / 默认 algorithm + algpseudocode），并打印 main.tex 还缺的 `\usepackage` 与 `\input`；③ 把每条 `% code:` 注释改写成数学语句——符号在正文里定义，`\Require` 写 `$\lambda = 0.1$` 这类带数值的超参（check 会对账 ref run），不写结果数字；④ 方法节正文写 Algorithm~\ref{alg:<id>}（无人引用的块 FAIL，G6b 清单里也有这一项）；⑤ `make_algorithm.py check`（G6d 里自动跑）。伪代码凭记忆写出来的是想要的方法，不是跑出结果的方法：锚到函数和 ref run 的参数，才对得上。manuscript.md 里块是 `**Algorithm N.**` 题注加 ```latex 围栏，数字 / 可读性 / 缩略语关口都不读它。

**可读性（G6f，`readability_check.py`，2026-10-23 新增）**：关口过了不等于稿子能读——三个真实项目的草稿每千词 48–52 个数字、贡献条目带 7–14 个数字、"preregistered/registered" 在正文出现 13–17 次、一篇已投稿的 blind.md 里 `\paragraph{` 被导成 `agraph{` 26 处。写作时守四条：① 协议簿记（预注册、addendum、被证伪的预测、约定变更、finding 编号、G 关口名）整体移到标题为 Protocol / Preregistration 的附录，正文只陈述结果和结论，附录由 readability_check 排除；② 每条贡献条目 ≤2 个数字、≤60 词，完整数字留给 Results 的表；③ 消融里不可解读的格子标在表 / 图本身（题注写 "grey cells not resolvable within seed noise"，make_figure.py 已经这样写；G6b 的 ablation-resolve 项现在认题注和表脚注），不在正文里逐格叙述；④ 引言与相关工作按 主题句 → 证据 → 对比 → 判断 写，不要排成引用目录（≥4 个引用且 ≥3 个分号的段落会被点名）。阈值来自 `references/readability-norms.csv`（已发表 CVPR/ICCV/ECCV/NeurIPS/MICCAI/WACV/AAAI、TMI/MedIA/TIP/TPAMI/IJCV、Nature 系的 90/95 分位；`readability_check.py calibrate` 可重算）：超过 95 分位 FAIL，超过 90 分位 WARN。LaTeX 稿另有 G6d 的残留标记检查（`\todo`/`\fixme`/`\hl`、未 disable 的 todonotes、.blg/.log 里的缺失引用键），文本稿有 `gate_check.py limits/submission` 的 TODO/FIXME/XXX/[待补充]/[TBD]/`??`/裸 bibkey 检查。
