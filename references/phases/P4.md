# P4 实验 — 细则

> SKILL.md 四行表的全文版，从 v2.5 的 SKILL.md 原文逐字下沉；进入 P4 前读完本文件再动手。关口判据与历史漏法见 [../gates.md](../gates.md)，失败模式总表见 [../lessons.md](../lessons.md)。

**P4 实验**：每 run 写 run_card；训完看 log 条数；主表只收一种硬件；每 5–10 run 回看 findings.md；对本文方法跑 `failure_slice.py` 出 results/failure_slices.md（最差切片、集中度、模型知不知道，进正文失败分析；缺则 G4 WARN）。**反常触发器**（results_check 查，分诊顺序见 [references/anomaly-triage.md](references/anomaly-triage.md)：口径→数据→泄漏→实现→真发现，findings.md 用 templates/findings.md 的块格式记 checked/cause/action，open 状态不得进正文）：基线复现与原论文报告值差超过 `reproductions` 的 tol（默认 2×报告 std），或任一 `predictions` 符号与预注册相反，必须先在 findings.md 写一条（含方法名与指标名）再继续训练，不许直接改配置——一半的时候反常本身就是论文（ESM-2 序列不预测共表达、kNN 读数低估嵌入都是这么来的）。G4 = `results_check.py` + `ablation_plan.py resolve` 全绿（溯源、口径、seeds、覆盖、预测符号、消融分辨率）。

**口径登记与日志适配器（v2.13）**：每个 run 的 `args.json` 登记五项口径键 `input_size`、`split`、`checkpoint_rule`（last / best-on-val / 固定 epoch）、`class_map`、`evaluator`（也可写进 `eval.json` 或 `protocol.json`，args.json 优先；键名在 `results.protocol_keys` 可改，支持 `a.b` 点路径）。G4 对同一对照集（主表按 `results.dataset_key`，默认 `dataset` 列，无此列即一整个集）里取值不止一种的键 FAIL，另立表或在 `results.protocol_waiver: {键: 理由}` 写明理由（降为 WARN，正文须说明；复现基线口径有意不同也要这样登记，不自动豁免）；没登记的键只给 INFO，只有部分 run 登记给 WARN——脚本只能查到你写下来的键。训练日志转曲线用 `log_adapters.py --adapter ultralytics|mmengine|lightning|csv|tensorboard --input <日志> --metric-col <列> --method M --dataset D --units fraction|percent --out results/curves_x.csv [--append]`：`--units` 必须显式给（fraction 会 ×100 并记入 units_in，不替你猜），缺口 / 重复 epoch / NaN 都会 WARN，输出直接喂 `make_figure.py curves --x epoch --y value --series method`；TensorBoard 的 step 常是 iteration，要加 `--step-is-epoch` 才当 epoch。
